# 项目总览

> 名字：AkiBurger Voice
> 文档版本：v0.3（2026-10）
> 变更：确认命名；参数原则改为"展示 + 教学"；新增情绪控制方案；v0.3.0 界面定稿（动漫游戏主界面 + 原创主视觉 5 表情 + galgame 对话框）

---

## 一、一句话说清这是什么

**一个集成开发软件，力争本地就能自己训练模型并且克隆出最像的声音，且可以自己调整优化的人声输出**

它做两件事：

1. **造声音** —— 导入一段音频，自动清洗、自动识别、自动训练、自动优化呈现，产出人声
2. **用声音** —— 选一个已经训练好的人声模型，只需输入文案，输出中文／英文／日文配音

---

## 二、要解决什么问题

### 现状（GPT-SoVITS 原界面）

功能齐全，但用起来是这样的：

| 痛点 | 具体表现 |
|---|---|
| **步骤散** | 切分在一个标签页、识别在另一个、训练又在另一个，来回切 |
| **参数要记** | 一堆滑块，不知道哪个重要，调好一次下次全忘 |
| **像开盲盒** | 训了一小时，出来好不好全凭运气，没有客观判断 |
| **报错看不懂** | 甩一堆堆栈信息，不知道该改什么 |
| **人工很重** | 几百段音频要一条条听、一条条校对 |
| **留不住** | 调好的配置没有地方存，下次从零开始 |

### 本项目要达成的效果

| 目标 | 怎么做到 |
|---|---|
| **一条线走完** | 素材 → 质检 → 标注 → 训练 → 评测 → 合成 |
| **参数可以学懂** | 高级参数展示出来，选择性进行优化，提供高级参数含义文档 |
| **训练有反馈** | 训完根据分数（无需给出输出）分类，让人更好的完成数据筛选工作 |
| **人工只花在刀刃上** | 自动挑出可疑的，只让人看那一小部分 |
| **配置留得住** | 预设可存、可取、可导出、可分享 |

### 明确不做的事

防止范围失控，以下内容**本项目不做**：

| 不做 | 原因 |
|---|---|
| ❌ 视频配音、换音轨 | 复杂度高，先把音频这条路做扎实 |
| ❌ 语音人声分离（去 BGM） | 当前阶段不做；若素材本身干净则不需要 |
| ❌ 手机版、网页版、在线服务 | 纯本地运行，声音不出本机 |
| ❌ 修改模型内部架构 | 收益低、成本高，本项目的优化在流程层，不在网络结构层 |
| ❌ 多用户、账号体系 | 单机单用户工具 |

## 三、给谁用

| 用户 | 特征 | 最在意什么 |
|---|---|---|
| **主用户：本项目的作者** | 有 RTX 4060 8G，已装 GPT-SoVITS，做游戏角色配音 | 声音像不像、训练效果好不好 |
| **次级用户：开源项目的使用者** | 有显卡、愿意折腾，可能没装过 GPT-SoVITS | 能不能装得上、跑得起来 |

**设计上要同时满足两种人**：

- 对作者：**要够深**，能调、能看数据、能对比，进行主动的优化训出贴合的声音，不用给出示例音频
- 对新用户：**要够简单**，装完就能用，不用读一堆文档，给出素材就能上手训练无需前置知识

> 这就是为什么"高级参数默认收起" —— 同一套界面，深浅两档。

## 四、核心思路

### 4.1 引擎选型：用已装好的，不另起炉灶

**合成与训练引擎：GPT-SoVITS**（本地已装，v2Pro / v2ProPlus 权重齐全）

**但要留活口**：引擎通过接口调用，不写死。以后想换 IndexTTS、CosyVoice 等更新的模型，只需要新增一个适配文件，界面一行不用改。

### 4.2 每一环都用该领域更强的工具，而不是最方便的

这是本项目与多数同类项目的核心差别。**大多数同类项目是"抓一个模型包一层界面"，本项目每一环都单独选过。**

详见 [`04-技术选型与调研.md`](04-技术选型与调研.md)。

### 4.4 一个音色说多种情绪 —— 不分批训练

**常见笨办法**：平静训一个模型、开心训一个模型、生气训一个模型，用的时候手动选。

**问题**：训练三遍、占三倍空间、切情绪要换模型，而且每个模型的数据都被切薄了。

**本项目的做法**：**一个音色模型，情绪在输出时由软件自动处理，用户不操心。**

```
输入文本
   ↓
软件读一遍文本，自动判断该用什么语气
   ↓
界面上显示判断结果（可以改）
   ↓
软件自己从训练数据里挑一段对应语气的片段（界面上不出现这一步）
   ↓
拿去合成，输出带这个语气的语音
```

**技术实情（已查证）**：GPT-SoVITS **没有**独立的情绪参数。
它的情绪来自**参考音频本身的语气** —— 喂一段"笑着说"的，它就带笑；喂一段"哭着说"的，它就带哭腔。
**参考音频必须存在，绕不过去。**

**但用户不需要参与这件事** —— 参考音频由软件从训练数据里自动挑选，界面上完全不出现。

**关键前提：高数据拟合。**
软件能挑出什么语气，取决于训练数据里真的有过这种语气。
数据丰富、情绪起伏多 → 语气自然；数据全是一本正经的念白 → **再怎么挑也挑不出笑声和哭腔**。

所以质检阶段有个额外要求：**识别并保留情绪特征明显的片段**，不能因为"听起来不一样"就当异常剔掉 —— 这些恰恰是最值钱的。

**为什么是"自动 + 可改"而不是全自动**：
配音台词的情绪经常是**反着的** —— "我很开心"可能是嘲讽，"没事"可能是快哭了。纯自动一定会翻车，所以判断结果必须摆在明面上，让人随手改。

**为什么不做"自动生成多版情绪让人挑"**：
会增加数倍合成耗时，收益不明显。**先把判断做准，让人能改，就够了。**

### 4.5 参数要展示，不要藏

**不采用"把高级参数藏起来防呆"的做法。**

理由：本软件的目标用户是**想练出好声音的人**，不是只想点一下就出结果的普通用户。藏起来反而挡住他们。

**做法**：

| 做法 | 说明 |
|---|---|
| 参数可见 | 想调随时能调 |
| 每个参数有解释 | 讲清是什么、什么时候该动、动了会怎样 |
| 提供含义文档 | 系统性的参数说明，不只是一句话提示 |
| 默认值即推荐值 | 不懂的人直接用，效果也是好的 |

这是整个项目最有价值的部分。

原界面训完只有 loss 曲线，看不出像不像。本项目：

```
训练完成
   ↓
自动用 N 句测试文本合成
   ↓
用声纹模型跟原始音频比对，算相似度分数
   ↓
给出分类
```

**没有这一步，训练就是玄学；有了这一步，才能谈"自主优化"。**

**同时必须承认**：相似度的上限由数据决定。软件能把参数、版本、流程做对，但素材不行就是不行。这一点要写进 README，避免用户误解。

## 五、整体架构

```
┌──────────────────────────────────────────────┐
│              应用层（外壳）                    │
│                                              │
│   数据地图 · 训练跑道 · 合成台 · 音色库          │
│   标注面板 · 评测对比 · 预设系统 · 新手保护      │
│                                              │
│   职责：好用、顺、不让用户碰原界面               │
└───────────────────┬──────────────────────────┘
                    │  三个标准接口（见第六节）
┌───────────────────┴──────────────────────────┐
│              能力层（内核）                    │
│                                              │
│   数据质检 · 标注纠错 · 训练编排                │
│   效果评测 · 参数推荐                          │
│                                              │
│   职责：让声音像、让训练有反馈                   │
└───────────────────┬──────────────────────────┘
                    │  文件 + HTTP 调用
┌───────────────────┴──────────────────────────┐
│           外部引擎（第三方，不修改）             │
│                                              │
│   GPT-SoVITS（训练/合成）                      │
│   FunASR（识别/切分/说话人检测）                │
│   ERes2Net（声纹打分）                         │
│   Ollama + Qwen3（文字纠错）                   │
└──────────────────────────────────────────────┘
```

### 为什么要分成两层

| 好处 | 说明 |
|---|---|
| **互不阻塞** | 界面和算法可以同时开发 |
| **可替换** | 换模型只动能力层，界面不动 |
| **可验证** | 算法改没改好，用同一批数据跑分就知道 |
| **可开源** | 别人想只拿界面、或只拿算法，都能拆开 |

## 六、三个标准接口

两层之间只通过这三个口通信。**这三个口定下来，两边就能各干各的。**

### 接口 ①：模型清单文件 `model.json`

能力层训练完一个音色，吐出这个文件。应用层只认它。

**要点**：应用层**不关心**模型怎么训出来的，只读这个文件来展示。

根据这个文件就可以直接上手在这个软件输出。

### 接口 ②：成品音频目录 `outputs/`

默认在这里，但可以自己修改出品在哪。

### 接口 ③：打分与情绪接口

**打分**：应用层传两段音频，能力层返回相似度分数与判定。

**情绪判断**：应用层传一段文本，能力层返回判断出的情绪与置信度，供界面显示与修改。

## 七、与 GPT-SoVITS 原环境的关系

**关键原则：不修改、不污染、不依赖其内部代码。**

```
你的电脑
├── GPT-SoVITS 原环境（9.3 GB）
│   └── 本项目只做两件事：
│       · 调用它的训练脚本
│       · 调用它的 HTTP 接口
│   ✗ 不改它的代码
│   ✗ 不动它的配置
│
└── 本项目（独立目录）
    └── 通过接口和它通信
```

**好处**：

- GPT-SoVITS 升级了，本项目不会崩
- 本项目出问题，不影响原有环境
- 别人不想用本项目，原环境照常能用

**环境复用策略**（决定新用户的体验）：

```
启动
  ↓
① 检测到已有 GPT-SoVITS 环境？
   有 → 直接复用（作者本人属于这种情况，零等待）
  ↓ 没有
② 检测到本项目已有独立环境？
   有 → 直接用
  ↓ 没有
③ 自动创建（约 10 分钟，一次性，之后永久复用）
   提示："第一次要准备环境，约 10 分钟，以后不用再等"
```

## 八、技术外形

**形态：桌面应用**

| 项 | 选择 | 理由 |
|---|---|---|
| 界面技术 | Web 技术（HTML/CSS/JS） | 数据地图、训练跑道这类视觉效果，用网页技术做效率高得多 |
| 桌面外壳 | 把界面装进桌面窗口 | 用户看到的是"一个程序"，不是浏览器标签页 |
| 后端 | Python | 要和 GPT-SoVITS、FunASR 这些 Python 生态对接 |
| 通信 | 本地 HTTP | 后端和界面分离，将来想改成纯网页版零成本 |

**为什么不用传统桌面控件（PySide/Qt）**：本项目重视界面表现力，数据地图、对比播放这些交互用传统控件实现代价太大。用 Web 技术，**以后想搬到浏览器上也是一行不用改**。
