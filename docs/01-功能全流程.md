# 功能全流程

> 本文档描述：用户从打开软件到拿到成品，每一步看到什么、软件在背后做什么、必须有哪些功能。

---

## 总览：两条路径

```
【路径 A：学习声音】第一次用，长，一次性
  启动 → 新建音色 → 导入素材 → 数据质检 → 标注 → 训练 → 评测 → 入库

【路径 B：生成人声】以后每天用，短，要快
  选音色的模型文件 → 输文案 → 合成 → 下载

              两条路径产出的"音色"是同一个东西
```

**界面设计要求：这两条路径是平级的两个主入口。**

不要出现"想训练请进设置页"这种设计 —— 路径 B 用得最多，路径 A 最重要，两个都得在第一屏点得到。

功能是这样的，UI设计滞后。

# 阶段 0 · 启动

## 用户看到什么

```
双击图标
   ↓
启动画面（3~10 秒，取决于环境是否就绪）
   ↓
首次运行 → 检测环境 如果有其他的非默认模型可以用就用？不能用就算了下载默认模型，同时提醒用户在配置环境，可以把默认模型的安装包藏在软件里面
```

## 软件背后做什么

1. 检测是否存在 GPT-SoVITS 环境 → 有则复用
2. 检测显卡型号与显存
3. 逐个核对模型清单（详见 [`05-模型与依赖清单.md`](05-模型与依赖清单.md)）
4. 在后台把 GPT-SoVITS 的接口服务拉起来
5. 体检通过后再显示主界面

## 必须有功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F0-1 | 环境自动检测 | 复用已有 GPT-SoVITS 环境，不重复安装 |
| F0-2 | 显卡检测 | 报告型号与显存，用于后续参数推荐 |
| F0-3 | 模型清单核对 | 按"缓存名"在标准位置查找，找到就跳过 |
| F0-4 | 按需下载 | 进度可见、支持断点续传、能选下载源、能跳过可选项 |
| F0-5 | 后台启动服务 | 用户不需要知道"还有个服务要开" |
| F0-6 | 环境自动创建 | 没有 GPT-SoVITS 环境时自动建（约 10 分钟，一次性） |
| F0-7 | 体检结果只出现一次 | 之后不再打扰，可在"关于"里复查 |

## 易错点

- 不管关不关掉窗口继续后台下载
- ❌ 把可选项也标成必需 → ✅ 也可以明确标注"跳过也行"
- ❌ 环境不满足时才报错 → ✅ 开局就查清

# 阶段 2 · 数据质检

> **这是让声音变像的第一道关。** 也是本项目区别于普通工具的地方。

## 用户看到什么

```
┌─ 数据地图 ──────────────────────────────────┐
│  xx-xx    312 段 · 48 分钟 · 日语            │

│   ⚠️ 7 段  背景有杂音                        │

│                                             │
│  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐            │
│  │▓▓│▓▓│▓▓│░░│▓▓│██│▓▓│▓▓│▒▒│▓▓│            │

│                                              │
│  已自动处理：8 段太短 · 7 段杂音 → 已移出待定区   │
│                                              │
│  [ 一键采纳全部建议 ]    [ 进入可疑音频筛查 ]        │
└──────────────────────────────────────────────┘

点任意方块 → 当场播放 + 自己选择去留
```

## 软件背后做什么

对每一段音频自动检查：

| 检查项 | 用什么 | 判断什么 |
|---|---|---|
| **说话人是否同一人** | 说话人检测 + 声纹比对 | **混入其他角色的声音 —— 这是相似度的隐形杀手** |
| 时长 | 直接量 | 太短学不到东西，太长学不细 |
| 噪音 | 信噪比、削波检测、混响检测 | 背景杂音、爆音、回声 |
| 文字是否对得上 | 识别文本长度 vs 音频时长 | "这句话根本念不完"这类错误 |
| 重复 | 音频指纹比对 | 同一句收了两遍 |

## 必须有功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F2-1 | 说话人检测 | 逐段判断有几个人在说话 |
| F2-2 | 声纹比对 | 与主角声纹比对，标出不是本人的段 |
| F2-3 | 时长检查 | 可配置阈值 |
| F2-4 | 噪音检测 | 信噪比 / 削波 / 混响 |
| F2-5 | 文字音频比对 | 发现长度严重不匹配的段 |
| F2-6 | 重复检测 | 找出内容重复的段 |
| F2-7 | 可视化地图 | 一段一个方块，颜色区分状态 |
| F2-8 | 点块即听 | 点开当场播放，不跳页、不弹窗 |
| F2-9 | 批量采纳 | 一键接受所有建议 |
| F2-10 | 逐条处理 | 想细看的人可以一条条过 |
| F2-11 | **可撤销** | 删错了能恢复 |
| F2-12 | 手动打标 | 用户能自己标记某段"保留/剔除" |
| **F2-13** | **情绪片段保留** | ⚠️ **不能把情绪强烈的段当异常剔掉** —— 这些是语气功能的原料，最值钱 |
| **F2-14** | **语气自动归类** | 顺手给每段标上语气（平静/开心/悲伤…），供合成时自动挑参考片段 |

## 易错点

- ❌ 一上来就让用户面对 312 个文件 → ✅ 默认自动处理完，只让人看标红的
- ❌ 显示"信噪比 12.3 dB" → ✅ 显示"背景有杂音，建议重录"
- ❌ 删了就没了 → ✅ 必须能撤销

```
│  │                                       │   │

│  │   2.3 秒念不完这句，可能有漏字。          │   │
│  │   「きて」在此语境更像「来て」            │   │
│  │                                       │   │
│  │   ┌─────────────────────────────────┐ │   │
│  │   │ ここに来て、やっと…              │ │   │  ← 可直接编辑
│  │   └─────────────────────────────────┘ │   │

│  键盘：空格播放 · 回车确认 · → 跳过            │
└────────────────────────────────────────────┘
```

## 软件背后做什么

1. **语音识别** —— 用 FunASR（日语准确率明显高于 Whisper，见 [`04-技术选型与调研.md`](04-技术选型与调研.md)）
2. **挑可疑的** —— 综合以下信号，只把可疑的交给用户：
   - 识别置信度低
   - 文本长度与音频时长明显不匹配
   - 同一段音频识别两次结果不一致
3. **本地 AI 纠错** —— 把可疑句交给本地语言模型（Ollama + Qwen3），结合语境给修改建议

**关键：全程本地，音频和文本都不出本机。**

## 必须有功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F3-1 | 批量语音识别 | 支持中／英／日 |
| F3-2 | 置信度评估 | 每段给出可信程度 |
| F3-3 | 自动挑可疑 | **只把可疑的交给用户，其余自动通过，但也可让人抽查** |
| F3-4 | 本地 AI 纠错建议 | 结合音频时长、语境给修改建议 |
| F3-5 | 播放与编辑同屏 | 边听边改，不来回切 |
| F3-6 | 全部键盘操作 | 空格播放、回车确认、方向键跳转 |
| F3-7 | 进度显示 | "第 1 / 23" |
| F3-8 | 批量替换 | 全局替换某些固定错误 |
| F3-9 | 标点处理 | 标点影响停顿，要和音频一致 |
| F3-10 | 自动保存 | 不用手动点保存 |
| F3-11 | 回退 | 改错了能撤 |

## 易错点

- ❌ 让用户逐条校对几百段 → ✅ 只让看 23 段，**目标是提高效率但不是极限效率，保证质量过完**
- ❌ 全靠鼠标点击 → ✅ 键盘流是必须的，鼠标点 23 次是最糟的设计
- ❌ 把纠错模型做成必需 → ✅ 它是可选的，不影响基本流程

# 阶段 4 · 训练

## 用户看到什么

```
┌─ 训练跑道 ────────────────────────────────┐
│                                           │
│  按你的数据量（48 分钟）和显存（8 GB）       │
│  自动推荐 2 组配置：                        │
│                                           │
│  ① v2Pro      轮数 8   ████████░░   87%   │
│  ② v2ProPlus  轮数 8   ██████░░░░   61%   │
│                                           │
│  预计剩余： ① 8 分钟  ② 26 分钟             │
│                                           │
│  [ ⏸ 暂停 ]  [ ➕ 加一组 ]  [ ⚙️ 自己配参数 ] │
│  [ 📋 详细日志 ]                            │
│                                           │
│  💡 训练期间可以去做别的，界面不会锁住        │
└───────────────────────────────────────────┘

期间保留的训练模型可以自主评价然后留下几种好的让人选，总之优化工作是重点，要生成效果好。

```

## 软件背后做什么

1. **参数推荐** —— 根据数据量、显存，推荐合适的模型版本与轮数
2. **自动试多组** —— 排队依次训练，跑完自动进入评测
3. **进度跟踪** —— 解析训练输出，换算成百分比与剩余时间
4. **断点续跑** —— 训练中断后能从上次的存档继续

## 必须有功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F4-1 | 参数自动推荐 | 按数据量、显存推荐，用户不用懂 |
| F4-2 | 自动试多组配置 | 这才是"自主训练"的实质 |
| F4-3 | 真实进度 | 百分比 + **剩余时间**（剩多久比百分比重要） |
| F4-4 | 断点续跑 | 关机、断电后能接着来 |
| F4-5 | 后台运行 | 训练时界面不锁，能去做别的。**同时控制资源占用，不要把 CPU 压满导致电脑没法用** |
| F4-6 | 训练完成通知 | 训一小时，人不可能盯着 |
| F4-7 | 智能保留存档 | **不用全留，也不能只留最新** —— 按分数保留若干候选，供后续对比选优 |
| F4-8 | 手动配参 | 想自己调的人能调，**附上每个参数的解释** |
| F4-9 | 失败诊断 | 显存不足、路径错误等，给人话解释和解决办法 |
| **F4-10** | **自主评价与留优** | 训练过程保留的多个存档，自动评分后**留下几种好的让人选**，差的自动清理 |

## 关于"自动试几组配置"

**已确定：不做自动参数搜索。**

原因：8 GB 显存下试 3 组要 3 小时，收益不如把数据洗干净、把版本选对。

**替代做法**：训练过程本身会存下多个轮次的权重，这些就是天然的候选。
软件自动给它们打分、分类，**留下好的几组让人挑**。这比"换参数重训"更省时间，而且用的是同一份数据。

**优化工作的重心**（用户明确要求：优化是重点，效果要好）：

1. 数据干净度（占相似度大头，见 [`04-技术选型与调研.md`](04-技术选型与调研.md)）
2. 从已有存档里挑最优，而不是盲目重训
3. 参数、版本、参考音频选对

## 易错点

- ❌ 转圈圈不给时间 → ✅ 必须给剩余时间估计
- ❌ 训练时锁住界面 → ✅ 训练一小时，但是期间可以随时观察情况，这中间要能干活
- ❌ 只留最新模型 → ✅ 保留多个候选，供后续对比

# 阶段 5 · 评测

> **这是让声音变像的第二道关，也是整个项目的灵魂。**

## 用户看到什么

```
┌─ 评测结果 ────────────────────────────────┐
│                                           │
│  自动合成 5 句测试文本，与原始音色比对声纹：    │
│                                           │
│  🥇 ③ v2ProPlus · 轮数12    相似度 0.81    │
│      ▶ 试听          [ 用它 ]              │
│                                           │
│  🥈 ② v2ProPlus · 轮数8     相似度 0.79    │
│      ▶ 试听                                │
│                                           │
│  🥉 ① v2Pro · 轮数8         相似度 0.74    │
│      ▶ 试听                                │
│                                           │
│  🤖 建议：③ 比 ① 提升 0.07，建议用 ③         │
│                                           │
│  📊 分类：好 1 个 · 可用 1 个 · 不行 1 个     │
│                                           │
│  ⚖️ [ 对比着听 ]                            │
│     可以自己输入示例文本，文本语言和输出      │
│     音频的语言可以不同（测跨语言）            │
└───────────────────────────────────────────┘
```

## 软件背后做什么

1. 用测试句让每个候选模型各合成一遍
2. 用声纹模型算每条合成音频与原声的相似度
3. 取平均分，排序
4. 生成人话结论

### 测试句从哪来（重要）

**评测要测两件事，不能用同一批句子：**

| 测什么 | 用哪些句子 | 看什么 |
|---|---|---|
| **本人语言** | 训练数据里的句子 | 这门语言说得像不像 |
| **跨语言** | 另外准备的中文句、英文句 | 说外语时声音还像不像 |

**为什么必须分两批**：

```
只用日语素材训练 → 测试句也全是日语
        ↓
只能验证"日语像不像"
        ↓
验证不了"用日语练的声音说中文/英文像不像"
```

而**跨语言正是本项目的核心能力**。不分两批测，这块就是"训完了不知道行不行"。

**注意**：用训练数据里的句子评分会偏乐观 —— 模型对见过的句子念得更好，相当于考做过的题。
所以两批分数要**分开显示**，让人知道哪个是"最佳水平"、哪个是"真本事"。

## 必须有功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F5-1 | 自动打分 | 用声纹模型算，不靠耳朵 |
| F5-2 | 自动合成测试句 | 训完自动跑，不用手动 |
| F5-3 | 测试句选择 | **分两批**：训练数据里的句子（测本人语言）＋另备的中/英句（测跨语言） |
| F5-4 | A/B 对比播放 | 同一句话不同版本无缝切换着听 |
| F5-5 | 人话结论 | "建议用 ③"，不是甩一堆数字 |
| F5-6 | 选定入库 | 一键把选中的变成可用音色 |
| F5-7 | 保留落选版本 | 以后可能还想对比或换回去 |
| F5-8 | 记录评测历史 | 同一音色多次训练的得分趋势 |
| **F5-9** | **分数分类** | 按分数分档（好/可用/不行），帮人快速筛数据、筛版本 |
| **F5-10** | **自定义对比文本** | 用户可自己输入示例文本，**文本语言与输出音频语言可以不同** |

## 设计要点

- **数字是辅助，耳朵是最终裁判** —— "试听"按钮必须和分数一样醒目
- **对比播放是关键功能** —— 同一句话切着听，差别一下就出来
- **跨语言必须单独测** —— 这是本项目的核心能力，不能糊过去
- **机器给建议，人拍板**

## 情绪是怎么工作的

**先说一个技术实情**：GPT-SoVITS **没有**独立的情绪参数。
它的情绪来自**参考音频本身的语气** —— 喂一段"笑着说"的，它就带笑；喂一段"哭着说"的，它就带哭腔。

**但参考音频必须存在**（这是它的工作原理，绕不过去）。

**所以本项目的做法是：把参考音频从"用户的操作"变成"软件的内务"。**

```
你输入文本
   ↓
软件读一遍，判断该用什么语气        ← 自动（本地大模型）
   ↓
判断结果摆在明面上，随时能改         ← 可改
   ↓
软件自己从训练数据里挑一段对应语气的片段   ← 这一步你看不见
   ↓
拿去合成
   ↓
你听到结果
```

**界面上不出现"选参考音频"这件事。** 用户只管选语气（或者不改，用软件判断的）。

### 关键在于"高数据拟合"

软件能挑出什么语气，取决于**训练数据里真的有过这种语气**。

| 数据情况 | 能出来的效果 |
|---|---|
| 数据丰富、情绪起伏多 | 软件能挑到笑声、哭腔、怒气，语气自然 |
| 数据平淡、全是平铺直叙 | **再怎么挑也挑不出情绪** —— 数据里本来就没有 |

⚠️ **这是一个硬前提**：情绪得在数据里真实存在过。

**所以质检阶段有一个额外要求**：识别并**保留**情绪特征明显的片段，不能因为"这段听起来不一样"就当异常剔掉。这些片段恰恰是最值钱的。

### 语气片段怎么归类

训练完成后自动做一遍：

```
扫描全部训练数据
   ↓
用本地模型判断每段的语气（平静/开心/悲伤/生气…）
   ↓
每种语气挑出最典型的 1~3 段
   ↓
存成这个音色的"语气素材"，供合成时自动选用
```

这一步是**自动的**，不需要用户动手。

**为什么"自动判断"还不够，必须让人能改**：
配音台词的情绪经常是**反着**的 —— "我很开心"可能是嘲讽，"没事"可能是强忍眼泪。纯自动一定会翻车。

**为什么不做"自动出多版情绪让你挑"**：
增加数倍合成耗时，收益不明显。**把判断做准、让人能改，就够了。**

| 编号 | 功能 | 说明 |

| F6-5 | 历史记录 | 合成的都留着，能回听、能重下 |
| F6-6 | 一键重来 | 改个字直接再合成 |
| F6-7 | 批量合成 | 贴一整段剧本，一次出一批文件 |
| F6-8 | 预设保存 | 调好的参数留得住 |
| F6-9 | 预设导出导入 | 能发给别人 |
| F6-10 | 快捷键 | `Ctrl+Enter` 合成、`空格` 播放 |

| F6-13 | 音量归一化 | 批量输出时音量一致 |
| **F6-14** | **情绪自动判断** | 读文本判断语气（平静/开心/悲伤/生气/惊讶/害怕） |
| **F6-15** | **情绪可手动改** | 判断结果摆在明面上，一键切换 |
| **F6-16** | **参考音频自动挑选** | 软件根据语气从训练数据里自己挑，**用户不参与、界面上不出现** |
| **F6-17** | **语气片段自动归类** | 训练数据里的情绪片段自动分好类，供 F6-16 使用 |
| **F6-18** | **跨语言输出** | 用日语素材练的音色，也能说中文和英文 |

## 设计要点

- **打开就能打字** —— 这是高频界面，减少一切多余步骤
- **参数不藏起来** —— 目标是让人学会调，不是防着人调坏。默认值是推荐值，想改随时改
- **情绪判断结果要显眼** —— 但要让人一眼看出"这是它猜的，我能改"
- **语气不一致要能立刻发现** —— 换参考音频后可以马上对比试听
- **历史记录是刚需** —— 配音时常出现"刚才那版好像更好"
