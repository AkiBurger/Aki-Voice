## 一、引擎侧（GPT-SoVITS）

### 坑 1：TorchCodec 加载失败，连音频都读不了

**现象**：
```
Failed to create AudioDecoder for xxx.wav: Could not load libtorchcodec
```

**根因**：
- torchaudio 2.9+ **强制**用 TorchCodec 读音频（`backend` 参数被忽略）
- TorchCodec 需要 FFmpeg 的**共享库 DLL**（avcodec/avformat/avfilter 等）
- 本机 `ffmpeg.exe` 是静态版，只有 exe 没有 DLL
- 而且 TorchCodec 各 core 版本依赖的 FFmpeg 版本 DLL 还不一样
  - core7 要 `avfilter-10.dll`（FFmpeg 8 的件）等
  - 系统里凑不齐

**解决**：不改依赖，改调用方 —— 用仓库里已有的 ffmpeg 后端加载函数替换 torchaudio.load：

```python
# GPT_SoVITS/TTS_infer_pack/TTS.py 的 _get_ref_spec() 里
# 本地修改：torchaudio.load 需要 TorchCodec，改用 ffmpeg 后端的 load_audio
import numpy as _np
from tools.my_utils import load_audio as _load_audio
raw_sr = self.configs.sampling_rate
_wav = _load_audio(ref_audio_path, raw_sr)
raw_audio = torch.from_numpy(_np.ascontiguousarray(_wav)).unsqueeze(0).float().to(self.configs.device)
```

**为什么可以这样改**：仓库里 `inference_webui.py` 和 `prepare_datasets/2-get-sv.py`
**已经有人做过同样的本地修改**，这只是补齐漏改的那一处，跟既有做法一致。

⚠️ **注意**：这算修改了 GPT-SoVITS 源码。升级 GPT-SoVITS 时会被覆盖，要重新打这个补丁。
启动脚本里把 `D:\Dev\tools\ffmpeg\bin` 加进 PATH 是必需的（`load_audio` 调 ffmpeg CLI）。

### 坑 2：英文合成缺 NLTK 数据

**现象**：
```
Resource 'cmudict' not found
Resource 'averaged_perceptron_tagger_eng' not found
```

**根因**：GPT-SoVITS 的英文前端用 NLTK，首次使用要下载数据，但 `raw.githubusercontent.com` 被墙，
自动下载失败（WinError 10054）。

**解决**：手动下载两个数据包放到 `%USERPROFILE%\nltk_data`：

| 包 | 目标目录 |
|---|---|
| `cmudict.zip` | `nltk_data/corpora/cmudict` |
| `averaged_perceptron_tagger_eng.zip` | `nltk_data/taggers/averaged_perceptron_tagger_eng` |

**可用的下载方式**（实测）：
- `cmudict.zip`（875 KB）：GitHub API 拿 base64 → 本地解码
  ```
  https://api.github.com/repos/nltk/nltk_data/contents/packages/corpora/cmudict.zip
  ```
- `averaged_perceptron_tagger_eng.zip`（1.5 MB）：API 超 1MB 不给内容，走 gh-proxy
  ```
  https://gh-proxy.com/https://raw.githubusercontent.com/nltk/nltk_data/gh-pages/packages/taggers/averaged_perceptron_tagger_eng.zip
  ```

**教训**：`raw.githubusercontent.com` 被墙，但 `api.github.com` 和 `gh-proxy.com` 可用。

## 二、训练侧

### 坑 3：病态识别文本把 pyopenjtalk 直接搞崩

**现象**：数据集制作第 1 步（提取文字特征）进程**无报错直接退出**，
返回码 `-1073740791`（STATUS_STACK_BUFFER_OVERRUN）。

**定位过程**：逐条跑 `clean_text()`，发现第 153 条文本是
**512 个连续的「え」**（FunASR 把一声拖长的「えーーー」识别成这样），
pyopenjtalk 处理时栈溢出崩溃。

**解决**：训练前先清洗数据（`data/setsuna/clean_data.py`）：

| 规则 | 剔除数 |
|---|---|
| 同一字符连续重复 > 6 次 | 14 条 |
| 文本长度 < 2 或 > 120 | 10 条 |
| 字数/秒 不合理（< 1 或 > 12） | 0 条 |
| **合计剔除** | **24 / 394** |

**教训**：ASR 输出必须质检。不质检的数据集会把训练管线直接搞崩，
而且崩得毫无提示，极难排查。

### 坑 4：配置文件里的中文路径被读乱

**现象**：SoVITS 训练启动后断言失败：
```
AssertionError  # data_utils.py: assert os.path.exists(self.path2)
```
但那个文件明明存在。

**根因**：临时配置 JSON 我用 UTF-8 写入（含中文路径 `02_GPT-SoVITS_配音`），
而 `s2_train.py` 用系统默认编码（GBK）读 → 路径变乱码 → 找不到文件。

**解决**：写临时配置时**全部转成 ASCII**：
```python
cfg_path.write_text(json.dumps(src, ensure_ascii=True), encoding="utf-8")
cfg_path.write_text(yaml.dump(src, allow_unicode=False), encoding="utf-8")
```

**教训**：Windows 中文路径 + Python 默认编码 = 定时炸弹。跨进程传路径时一律 ASCII 转义。

### 坑 5：保存权重时目录不存在

**现象**：训练跑完 2 轮后崩：
```
FileNotFoundError: [WinError 3] 系统找不到指定的路径:
'1792223174.5120182.pth' -> '.../logs_s2_v2Pro/G_233333333333.pth'
```

**根因**：webui 会先建好 `logs_s2_{version}/` 目录再调训练脚本，我的脚本漏了这步。

**解决**：训练前手动建目录：
```python
(OPT_DIR / f"logs_s2_{VERSION}").mkdir(parents=True, exist_ok=True)
(OPT_DIR / f"logs_s1_{VERSION}").mkdir(parents=True, exist_ok=True)
(SOVITS_ROOT / f"GPT_weights_{VERSION}").mkdir(parents=True, exist_ok=True)
```

### 坑 6：Python 3.13 的 tokenize 偶发崩溃（环境问题）

**现象**：不定时出现，随机发生在任何 `import torch` / `import transformers` 的地方：
```
File "tokenize.py", line 583, in _generate_tokens_from_c_tokenizer
    yield TokenInfo._make(info)
TypeError: Expected 5 arguments, got 5
```
或者文件读竞态导致的 `STATUS_STACK_BUFFER_OVERRUN`。

**特征**：**同一段代码单独跑就正常**，只有高频启停子进程时偶发。

**解决**：所有外部步骤加**自动重试**（实测重试即可通过）：
```python
for attempt in range(1, retries + 1):
    p = subprocess.run(...)
    if p.returncode == 0: return
```
另外清掉可能损坏的 `__pycache__` 也有效。

**教训**：Windows + 杀毒软件 + 大量 Python 子进程 = 偶发文件读竞态。
关键步骤必须可重试，不能一次失败就放弃。

## 三、应用侧

### 坑 7：双击启动脚本打不开（原因很隐蔽）

**现象**：用户双击 `启动.bat`，窗口一闪就没了，什么也没发生。但我从命令行跑同样的脚本正常。

**根因**：`write` 工具写出的 .bat 是 **UTF-8 编码**，而 Windows cmd 双击运行时按**系统 GBK 解码**。
脚本里的中文路径（`02_GPT-SoVITS_配音`）变成乱码 → 找不到 python.exe → 静默退出。

**解决**：
1. **整个 .bat 只写 ASCII**（一个中文字都不留，注释也用英文）
2. 用通配符自动定位中文目录，避免把中文写死在脚本里：
   ```bat
   for /d %%i in ("D:\Dev\ai\02_GPT-SoVITS_*") do set "SOVITS_ROOT=%%i\GPT-SoVITS"
   ```

**教训**：Windows 批处理文件**绝不能含非 ASCII 字符**（除非确定编码一致）。

### 坑 8：参考音频必须在 3~10 秒

**现象**：
```
参考音频在3~10秒范围外，请更换！
```

**解决**：参考音频从训练数据里按真实时长筛选（用 `soundfile.info` 读帧数/采样率），
并且**配套保存参考文本**（`ref_texts.json`）—— 训练后的模型带参考文本合成更稳。
