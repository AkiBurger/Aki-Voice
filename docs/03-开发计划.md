# 一、总原则

## 1.1 分期顺序的依据

**"越好验证的先做"** —— 一期比一期依赖更多前置条件，一期比一期难验证。

| 期 | 内容 | 验证需要什么 | 难度 |
|---|---|---|---|
| 第一期 | 合成台（含情绪） | 只需模型（已有） | ⭐ |
| 第二期 | 评测打分 | 需要**训练过的模型** | ⭐⭐ |
| 第三期 | 训练流程 | 需要**真实音频素材** | ⭐⭐⭐ |
| 第四期 | 素材全流程 | 需要**大量真实音频** | ⭐⭐⭐⭐ |

**第一期不需要任何音频素材**，用 GPT-SoVITS 自带的示例音频就能验证。这是为什么它排第一。

## 1.2 但架构一次到位

**代码结构一开始就按"四期全有"来设计**，不做临时方案。

```
src/
├── 应用层/
│   ├── 界面/            （第一期：合成台）
│   │   ├── 音色库/      （骨架先留）
│   │   ├── 合成台/      （第一期做）
│   │   ├── 数据地图/    （第四期做，先留空）
│   │   ├── 标注/        （第四期做，先留空）
│   │   ├── 训练/        （第三期做，先留空）
│   │   └── 评测/        （第二期做）
│   └── 通用/            （第一期做：任务栏、通知、快捷键）
│
└── 能力层/
    ├── 引擎/            （第一期做：接 GPT-SoVITS）
    ├── 评测/            （第二期做）
    ├── 训练/            （第三期做）
    ├── 质检/            （第四期做，先留空）
    └── 标注/            （第四期做，先留空）
```

**留空目录不是浪费** —— 它让每一期的新代码有明确归属，不需要重构。

# 二、四期计划

## 第一期 · 合成台

**目标：能听到第一段克隆出来的声音。**

| 项 | 内容 |
|---|---|
| 交付 | 桌面程序能打开；能选音色、选语言、输文案、**自动判断语气并允许修改**、点合成、听到结果、下载文件 |
| 含功能 | F0-1~F0-5、F6-1~F6-18、G-1~G-8 |
| **不需要** | 音频素材（用 GPT-SoVITS 自带示例音频验证） |
| 预计 | 前期工作量的主要部分 |

### 验收标准

- [ ] 双击图标能打开程序，不报错
- [ ] 自动检测到本机 GPT-SoVITS，并能在后台拉起服务
- [ ] 能用自带示例音频合成出一段中文、一段日文、一段英文
- [ ] **长文案（500 字以上）能自动切分并拼成完整文件**
- [ ] **输入一句台词，软件能自动判断语气，并允许手动改**
- [ ] **同一个音色，能用不同语气说出同一句话**
- [ ] 合成历史能回听、能重新下载
- [ ] 参数默认展开，每个都有中文说明，另有参数含义文档入口
- [ ] 预设能存、能取、能导出
- [ ] 全流程能用键盘完成（`Ctrl+Enter` 合成）
- [ ] 亮色动漫游戏主题 + 响应式布局（1440 基准，1000 / 860 等断点）都能用，窗口放大缩小都正常

### 里程碑

**听到第一段克隆音频，并且同一个音色能用不同语气说话。**
这一刻整个项目从"设想"变成"东西"。

---

## 第二期 · 评测打分

**目标：把"像不像"变成看得见的数字，按分数分类留优。**

| 项 | 内容 |
|---|---|
| 交付 | 能对多个模型版本自动打分、按分数分类、排序、对比试听 |
| 含功能 | F5-1~F5-10 |
| **前置条件** | 至少有一个训练好的模型（可用现有权重先验证流程） |
| 预计 | 中等 |

### 验收标准

- [ ] 对同一音色的多个模型版本，能自动各合成测试句
- [ ] **测试句分两批**：训练数据里的句子（测本人语言）＋另备的中/英句（测跨语言）
- [ ] 能算出相似度分数，**两批分数分开显示**
- [ ] 能按分数分类（好 / 可用 / 不行），帮人快速筛版本
- [ ] 能排序，并给出"建议用哪个"的人话结论
- [ ] 对比试听能用键盘 `1` `2` `3` 快速切换
- [ ] **对比试听支持自定义文本，且文本语言与输出语言可以不同**
- [ ] 历史得分能保存，能看出多次训练的趋势

### 为什么它排第二

**它是"自主留优"的前提。** 没有裁判，一堆候选模型里不知道哪个好。

而且零件都已在本机 —— 声纹模型是现成的。

---

## 第三期 · 训练流程

**目标：在软件里一键开练，训完自动评测。**

| 项 | 内容 |
|---|---|
| 交付 | 能导入音频、发起训练、看进度、**自动评分留优**、选定入库 |
| 含功能 | F1-1~F1-7、F4-1~F4-10、接口 ① ② ③ 全部打通 |
| **前置条件** | 🔴 **必须有真实音频素材** |
| 预计 | 中等偏大 |

### 验收标准

- [ ] 能拖入音频（文件/文件夹/长录音）
- [ ] 能按数据量和显存自动推荐参数
- [ ] 进度显示百分比 + **剩余时间**
- [ ] **训练时控制资源占用，不把 CPU 压满，电脑还能正常用**
- [ ] 训练中断后能续跑
- [ ] 训练时界面不锁，**可以随时回来看进度和日志**
- [ ] **多个轮次的存档按分数分类，留下好的几版供挑选，差的自动清理**
- [ ] 训完自动评测并给出建议
- [ ] 选定的模型能一键入库，立刻能用于合成（含情绪）

### 关于"自动试多组配置"

**已确定不做。** 理由：8 GB 显存下试 3 组约 3 小时，收益不如把数据洗干净、把版本选对。

**替代做法**：训练本身会产生多个轮次的权重存档，这些就是天然候选。
软件自动评分、分类、保留好的几版让人挑 —— 比"换参数重训"省时间，用的还是同一份数据。

**优化工作的重心**（用户明确要求：优化是重点，效果要好）：
1. 数据干净度（占相似度大头）
2. 从已有存档中挑最优，而不是盲目重训
3. 参数、版本、参考音频选对

### 🔴 这一期的硬门槛

**必须有真实音频。** 没有素材，这一期无法验证。

音频来源三选一：

1. 自己录（10~15 秒起，最好 5 分钟以上）
2. 从游戏提取（工具已备齐）
3. 先用 GPT-SoVITS 自带样本走通流程（验证流程可以，验证效果不行）

## 第四期 · 素材全流程

**目标：从一堆乱音频到干净可用的训练集，全自动 + 少量人工。**

| 项 | 内容 |
|---|---|
| 交付 | 数据质检 + 自动识别 + 抽查标注，全流程打通 |
| 含功能 | F2-1~F2-12、F3-1~F3-11 |
| **前置条件** | 🔴🔴 **必须有大量真实音频**（几百段级别） |
| 预计 | 大 |

### 验收标准

- [ ] 数据地图能一屏显示几百段，颜色区分状态
- [ ] 能自动检测混入的其他说话人
- [ ] 能自动检测时长、噪音、文字不匹配
- [ ] 点任意方块当场播放
- [ ] 能批量采纳建议、能逐条处理、**能撤销**
- [ ] 自动识别文字，**只把可疑的交给用户**
- [ ] 本地 AI 能给出纠错建议
- [ ] 标注全程键盘操作，23 条能在 2 分钟内过完

### 这一期最费事的原因

- 要处理的边界情况最多（各种格式、各种噪音、各种切坏的段）
- 说话人检测需要额外的模型和比对逻辑
- **界面复杂度最高**（数据地图、标注面板）

## 4.3 工作目录约定

**所有代码、输出、素材一律放在 `D:\Dev\projects` 下。**

```
D:\Dev\projects\
├── voice-studio\              ← 本项目
│   ├── README.md
│   ├── docs\                  ← 设计文档（已完成）
│   ├── src\                   ← 源代码（待写）
│   ├── assets\                ← 截图、演示素材
│   ├── data\                  ← 素材与中间产物（不进仓库）
│   └── outputs\               ← 合成结果（不进仓库）

```

**理由**：
- 集中管理，不散落各处
- `git init` 一次就能推
- 素材和输出都在项目内，方便整体搬迁

**注意**：`data\` 和 `outputs\` 必须写进 `.gitignore`，否则仓库会传不上去。

# 五、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| **音频素材不到位** | 高 | 第三、四期无法验证 | 先用自带样本走通第一、二期；同时尽快解决素材 |
| **8 GB 显存吃紧** | 中 | 训练慢、可能失败 | 参数按显存自动推荐；同时跑的任务数自动控制 |
| **训练压满 CPU 导致电脑卡** | 高 | 电脑没法用 | 提供资源占用控制，可限速 |
| **情绪判断判错** | 高 | 输出语气不对 | **判断结果必须摆在明面上可改**（纯自动一定翻车） |
| **跨语言效果不理想** | 中 | 核心能力打折扣 | 独立评测跨语言，不达标就在 README 里照实说 |
| **界面技术栈选错** | 低 | 返工成本高 | 第一期就定死，用 Web 技术 + 桌面外壳 |
| **GPT-SoVITS 升级导致不兼容** | 中 | 功能失效 | 只通过接口和脚本调用，不依赖其内部代码 |
| **训练脚本调用方式变化** | 中 | 训练功能失效 | 能力层做适配，界面不受影响 |
| **相似度提升低于预期** | 中 | 用户失望 | **README 里提前说明：数据决定上限**，不夸大 |
| **开源后被指滥用** | 中 | 项目声誉受损 | 加确认提示 + 免责声明 + 合规说明 |

## 关于"相似度提升低于预期"这条

这是最需要提前管理的预期。必须反复讲清楚：

> **相似度的上限由数据决定。** 软件能做的是：把数据洗干净、把标注弄对、把参数选好、把版本挑对。
> 但一段满是杂音的录音，任何软件都救不回来。

**把这句话写进 README，是对用户负责，也是对自己的保护。**
