# 一、为什么模型不能进仓库

| 原因 | 具体数字 |
|---|---|
| **GitHub 单文件限制** | 超过 **100 MB** 直接拒绝。本项目最大的模型文件是 **1.9 GB** |
| **仓库体积** | 本项目需要约 **2~8 GB** 模型。GitHub 建议仓库控制在 1 GB 内 |
| **Git LFS 也不够** | 免费额度 **1 GB 存储 / 1 GB 月流量**，**一个人 clone 一次就超了** |
| **协议问题** | 模型是第三方作品。**再分发等于替原作者授权**，不合规 |

## 所以采用三层策略

```
🟢 第一层：进仓库（几 MB）
   代码 + 配置 + 模型清单.json + 预设文件

🟡 第二层：首次启动自动下载
   按清单逐个检查 → 缺的才下 → 带进度、断点续传、可选下载源

🔵 第三层：缓存在标准位置，所有项目共享
   存在 HuggingFace 标准缓存目录，不放在项目文件夹内
```

## 二之二、情绪控制不需要额外模型

**这一点要写清楚，避免误以为还得装新东西。**

已查证：GPT-SoVITS **没有独立的情绪参数**，它的情绪来自**参考音频本身的语气**。
参考音频必须存在（这是它的工作原理），但**用户不参与挑选** —— 由软件从训练数据里自动选。

所以情绪功能靠的是：

| 需要的东西 | 从哪来 | 要额外下载吗 |
|---|---|---|
| 判断文本该用什么语气 | 关键词规则 v1（`src/backend/emotion.py`；后续可换本地 Qwen3） | ❌ 不用 |
| 每种语气的参考片段 | **从训练数据里自动挑 + 自动归类**（`data/setsuna/build_tones.py` → `data/ref/tones/`） | ❌ 不用 |

**v0.2 已落地**：生成脚本从清洗后的训练数据按 6 种语气各挑 1~2 条 3~7.5 秒的片段，
写到 `data/ref/tones/` 和 `tones.json`；合成时按语气自动换参考音频（参考音频 / 参考文本始终是日语），
没有这个库时退回默认参考音频。生成方式：`python data/setsuna/build_tones.py`。

**换句话说：情绪这块一个字节都不用额外下。**

⚠️ **硬前提**：软件能挑出什么语气，取决于训练数据里真的有过这种语气。
数据里没有的情绪，软件变不出来。这一点要写进 README。

# 四、自动下载的交互设计

```
┌────────────────────────────────────────────┐
│  需要准备以下组件                            │
│                                            │
│  ✅ Fun-ASR-Nano       已找到（跳过）         │
│  ✅ FSMN-VAD           已找到（跳过）         │
│  ⬇️ Qwen3 文字纠错       5 GB   [ 跳过也行 ]  │
│                                            │
│  下载源  (●) ModelScope  快                 │
│          ( ) HuggingFace                    │
│                                            │
│  保存位置  D:\Dev\cache\huggingface\hub      │
│                                    [ 更改 ]  │
│                                            │
│  [ 开始 ]    已有 9/10，无需下载也能用         │
└────────────────────────────────────────────┘
```

## 设计要点

| 要点 | 说明 |
|---|---|
| **先找再下** | 每个模型先按缓存名在标准位置查找，**找到就跳过，一秒不花** |
| **能选下载源** | ModelScope（国内快）/ HuggingFace（通用） |
| **可选项明确标注** | "跳过也行"，不吓唬用户 |
| **能改保存位置** | 模型很大，用户可能想放别的盘 |
| **可后台下载** | 关掉窗口继续下，不锁界面 |
| **断点续传** | 断网、关机后能接着下 |
| **校验完整性** | 下完按关键文件核对，损坏的重下 |

# 五、缓存位置：为什么放在标准目录

```
D:\Dev\cache\huggingface\hub\           ← HuggingFace 标准缓存目录
├── models--FunAudioLLM--Fun-ASR-Nano-2512
├── models--funasr--fsmn-vad
└── ...
```

| 好处 | 说明 |
|---|---|
| **多项目共用** | 以后做第二个项目用到同一个模型，不重复下载 |
| **能整体搬走** | 拷到新电脑，改一下路径设置，不用重下几个 GB |
| **与他人共享** | 别人已装过相同模型，自动识别、直接复用 |
| **符合生态惯例** | 和 HuggingFace 生态一致，别的工具也能用 |

**配置里提供"模型目录"设置项，允许用户指向已有目录。**

# 六、Python 环境依赖

## 6.1 版本要求（必须锁死）

| 组件 | 版本要求 | 备注 |
|---|---|---|
| GPT-SoVITS | Python **3.10 ~ 3.11** | 官方锁定 `< 3.12` |
| FunASR | 较宽松 | —— |
| 本项目界面层 | 较宽松 | —— |
| **现有环境实测** | Python **3.13** + torch **2.11.0+cu130** | GPT-SoVITS 已在此环境跑通 |

⚠️ **重要教训**：绝不能不指定版本就自动安装。
曾有项目因为不锁 Python 版本，自动建出 3.14 环境，而 torch 没有对应安装包，导致永远装不上、且重试会一直复用坏环境。

## 6.2 环境复用优先级

```
① 复用已有的 GPT-SoVITS 环境     ← 作者本人属于这种情况
② 复用本项目已建的环境
③ 新建（约 10 分钟，一次性）
```

## 6.3 环境创建工具：uv

| 优势 | 说明 |
|---|---|
| 速度快 | 明显快于 pip |
| 可指定 Python 版本 | 不依赖用户预装 |
| 依赖锁定 | 别人装出来的环境一致 |

# 九、协议与合规

## 9.1 分层处理

| 对象 | 处理方式 |
|---|---|
| **本项目代码** | 由作者选择开源协议（建议 MIT 或 Apache-2.0） |
| **第三方模型** | **只提供下载地址，不分发文件** |
| **第三方代码库** | 引用，不复制 |

## 9.2 为什么"只给地址"是正确做法

- 用户从官方源下载，**等于直接接受原作者的条款**
- 本项目不在中间承担授权责任
- 原作者更新模型时，用户能拿到最新版

## 9.3 README 中必须写明的

1. 本项目会下载哪些模型，各自来自哪里
2. 各模型的协议名称与链接
3. 各模型是否允许商用
4. 使用者需自行遵守各模型协议

## 9.4 声音使用的合规提示

- 界面首次使用声音克隆功能时，显示一次确认提示
- README 中明确：**只应使用自己拥有授权的声音**
- 克隆他人声音涉及声音权，多国法律有明确规定

**这不是走过场。同类项目因忽视这一点被下架的情况真实存在。**
