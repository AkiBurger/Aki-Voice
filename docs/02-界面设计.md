# 界面设计

> 本文档定的是"界面的规矩"。做的时候照着走，不跑偏。
> 目标：**让人用得舒服**

---

# 一、十一条设计原则

这是整个界面的宪法。任何设计有疑问，回来对这几条。

## 1. 主流程永远可见

顶部一条流程导航，随时知道自己在第几步、下一步是什么。

```
 ●━━━━━●━━━━━●━━━━━◉━━━━━○━━━━━○
素材   质检   标注   训练   评测   合成
                 ↑ 你在这
```

- 已完成的阶段：可点击回看
- 当前阶段：高亮
- 未开始的阶段：灰显，但看得见
- **不能出现"我不知道现在该干什么"的状态**

## 2. 给结论，不给数据

| ❌ 不要这样 | ✅ 要这样 |
|---|---|
| 信噪比 12.3 dB | 背景有杂音，建议重录 |
| epoch 12, loss 0.0231 | 训练完成，效果比上一版好 |
| 相似度 0.8134 | 相似度还可以 |
| CUDA out of memory | 显存不够了 |

**专业数据可以藏在"详情"里，但主界面说人话。**

## 3. 参数要展示，要教明白

**不采用"把高级参数藏起来防呆"的做法。**

本软件的目标用户是**想练出好声音的人**，不是只想点一下就出结果的普通用户。藏起来反而挡住他们。

| 做法 | 说明 |
|---|---|
| **参数可见** | 默认展开，想调随时能调 |
| **每个参数配一句人话说明** | 讲清是什么、什么时候该动、动了会怎样 |
| **另附参数含义文档** | 系统性的说明，不只是一句话提示 |
| **默认值即推荐值** | 不懂的人直接用，效果也是好的 |

```
语速          ├──●──────┤  正常
              └ 说话快慢，1.0 是正常语速，超过 1.3 会明显不自然

稳定性        ├──────●──┤  高
              └ 调高更稳但略呆板，调低更自然但可能念错字
```

**判断标准**：用户看完这个界面，应该**比用之前更懂这个东西**，而不是更迷糊。

## 4. 每一个等待都有交代

任何超过 3 秒的操作，必须显示三件事：

```
在做什么     正在识别第 47 / 289 段
还剩多久     约剩 2 分钟
能不能中断   [ 取消 ]
```

**禁止**：只转圈圈、只显示"处理中"、进度条卡在 99% 不动。

## 5. 危险操作能撤销

| 操作 | 保护方式 |
|---|---|
| 删除音频段 | 撤销按钮 + 保留在"已剔除"区 |
| 覆盖已训练模型 | 二次确认 + 旧版本自动保留 |
| 清空历史 | 二次确认 |
| 删除音色 | 二次确认 + 提示占用空间 |

**凡是不能撤销的，必须二次确认。**

## 6. 高频操作键盘流

标注、合成这两个高频环节。

| 场景 | 快捷键 |
|---|---|
| 标注 | `空格` 播放 · `回车` 确认 · `→` 跳过 · `Delete` 删除 |
| 合成 | `Ctrl+Enter` 合成 · `空格` 播放 · `Ctrl+S` 存预设 |
| 通用 | `Ctrl+Z` 撤销 · `Ctrl+Y` 重做 · `Esc` 关闭弹层 |

## 7. 长任务不锁界面

训练一小时，这中间必须能去做别的。

```
✗ 错误做法：弹出模态框，训练完才能关
✓ 正确做法：训练进后台，界面上有个常驻的小进度条
```

**常驻任务栏**（界面底部或侧边）：

```
┌──────────────────────────────────┐
│ 🔄 训练中  ② v2ProPlus  61%  26分钟│
│ 🔄 识别中  47/289              │
└──────────────────────────────────┘
点一下 → 展开详情；点 ✕ → 取消
```

## 8. 出错说人话

每条错误必须包含三部分：

```
出了什么问题    显存不够了
为什么会这样    显存装不下这么多任务
该怎么办        先别急着继续，去把别的任务停掉
```

**最后一项最重要 —— 给出可点的解决办法，不要只告诉用户"错了"。**

## 9. 深色为主

理由：

- 配音常在晚上做
- 波形、数值、对比界面在深色下更清晰
- 长时间看不累

**同时提供浅色主题**，但深色是默认。

## 10. 一处一个主按钮

每一屏有**一个**视觉上最重的按钮，就是这一步最该点的那个。

```
[ 开始训练 ]   ← 主按钮，实心、醒目
[ 返回 ]       ← 次要，描边
[ 高级设置 ]   ← 弱化，纯文字
```


## 11. 空状态要教人做事

第一次打开，**不给人一片空白**，而是让他做第一个选择：

```
┌────────────────────────────────────────────────┐
│                                                │
│              AkiBurger Voice                   │
│                                                │
│        你想做什么？                              │
│                                                │
│   ┌──────────────────┐  ┌──────────────────┐   │
│   │   🎤 创造音色      │  │   📂 导入已有音色  │   │
│   │                  │  │                  │   │
│   │  从一段音频开始     │  │  导入别人分享的    │   │
│   │  训练属于你的声音   │  │  音色文件直接用    │   │
│   └──────────────────┘  └──────────────────┘   │
│                                                │
│               [ 看三分钟教程 ]                   │
└────────────────────────────────────────────────┘
```

**两个入口对应两条路径**（见 [`01-功能全流程.md`](01-功能全流程.md) 总览）。

**新手不该面对空白，也不该猜"我该点哪个"。**

# 二、视觉规范（草案）

## 2.1 配色

| 用途 | 深色主题 | 说明 |
|---|---|---|
| 背景 | `#14161a` | 近黑，不刺眼 |
| 卡片 | `#1c1f26` | 比背景略亮 |
| 边框 | `#2a2f3a` | 极低对比，只做分隔 |
| 主文字 | `#e8eaed` | 不用纯白，减疲劳 |
| 次文字 | `#9aa0aa` | 说明、单位 |
| **主色** | `#4a9eff` | 蓝，用于主按钮、选中 |
| **成功** | `#3ecf8e` | 绿，通过、完成 |
| **警告** | `#f5a623` | 橙，存疑、需确认 |
| **危险** | `#ef4a5a` | 红，问题、删除 |

**用色原则：颜色只用来传达状态，不做装饰。** 界面整体应该偏灰，只有"需要你注意的地方"才出现颜色。

## 2.2 数据地图的颜色语义（重要）

数据地图用颜色表达质量，**这套语义要统一**：

| 颜色 | 含义 | 用户动作 |
|---|---|---|
| 🟢 绿 | 好，自动通过 | 不用管 |
| 🟠 橙 | 存疑，建议看看 | 可抽查 |
| 🔴 红 | 有问题 | 必须处理 |
| ⚫ 灰 | 已剔除 | 可恢复 |

## 2.3 字号层级

| 层级 | 用途 |
|---|---|
| 24-28px | 页面主标题 |
| 18-20px | 区块标题 |
| 15-16px | 正文（默认） |
| 13-14px | 说明文字、单位 |
| 12px | 极限次要信息 |

**正文不小于 15px** —— 配音工作要盯着看细节，字小了累。

## 2.4 间距

统一用 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48。

**信息密集的界面（数据地图、标注）用 8 和 12；留白界面用 24 和 32。**

```
├──────────────────────────────────────────────────────┤
```

**要点**：

- 底部"最近合成"—— 日常最常用的入口，不用先进音色

```
└──────────────────────────────────────────────────────┘
```

## 4.2 交互细节

| 行为 | 效果 |
|---|---|
| 点击方块 | 下方展开详情并**自动播放** |
| 悬停方块 | 显示提示气泡：时长 + 状态 |
| 方向键 | 在方块间移动 |
| `空格` | 播放 / 暂停 |
| `Delete` | 剔除当前段 |
| `Enter` | 保留当前段并跳到下一个有问题的 |
| 选中多个（Shift / Ctrl） | 批量操作 |

## 4.3 为什么这样设计

- **把质量变成视觉模式** —— 哪一片有问题，一眼看得出来，不用逐条听
- **点开即听，不跳页** —— 保持上下文，处理起来快
- **给结论不给数字** —— 说"疑似混入其他角色"，不说"说话人余弦距离 0.42"

# 五、标注界面（核心创新点 3）

## 5.1 布局

标注界面**故意做得极简**，因为目标就是快。

```
┌──────────────────────────────────────────────────────┐
│  标注确认                    第 1 / 23  ⚠️             │
├──────────────────────────────────────────────────────┤
│                                                      │
│              ▶  播放这段音频  (2.3 秒)                 │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │  ここに来て、やっと…                            │  │
│  │                                                │  │
│  └────────────────────────────────────────────────┘  │
│                                                      │
│  🤖 校对建议                                         │
│  2.3 秒念不完这句，可能有漏字。                          │
│  「きて」在此语境更像「来て」                            │
│                                                      │
│                                                      │
│   [ ✅ 对 ]      [ ✏️ 改好了 ]      [ 🗑 删掉 ]        │
│                                                      │
│                                                      │
│  键盘：空格播放 · 回车确认 · → 跳过 · Del 删除           │
├──────────────────────────────────────────────────────┤
│  进度 ████████░░░░░░░░░░░░  4 / 23 已确认             │
└──────────────────────────────────────────────────────┘
```

## 5.2 交互细节

| 行为 | 效果 |
|---|---|
| 进入界面 | **自动播放第一条** —— 不用再点一次播放 |
| `空格` | 播放 / 重播 |
| `回车` | 确认"对"，自动跳下一条并播放 |
| `→` | 跳过（先不管，最后再回来） |
| `Delete` | 删除这条 |
| 编辑文本框 | 改完按 `Tab` 或点击别处即保存 |
| 全部处理完 | 自动提示可以进入下一步 |

## 5.3 为什么这样设计

**这个界面的唯一目标是：让 23 条在两分钟内过完。**

- **自动播放** —— 省掉"点播放"这个动作 ×23 次
- **键盘流** —— 手不离键盘
- **建议放显眼位置** —— 用户只需判断"对不对"，不用自己想
- **大按钮** —— 点击目标大，不容易点错

# 六、训练跑道界面（核心创新点 2）

## 6.1 布局

```
┌──────────────────────────────────────────────────────┐
│  训练中                                              │
├──────────────────────────────────────────────────────┤
│  按你的数据量（48 分钟）和显存（8 GB）推了 2 组配置      │
│                                                      │
│  ① v2Pro · 轮数8                                     │
│     ████████████████████  100%   已完成  ● 0.74       │
│                                                      │
│  ② v2ProPlus · 轮数8                                 │
│     █████████████░░░░░░░   61%   约剩 26 分钟          │
│                                                      │
│  ─────────────────────────────────────────────        │
│  [ ⏸ 暂停 ]  [ ➕ 加一组配置 ]  [ 📋 日志 ]            │
│  [ ⚙️ 我自己配参数 ]                                   │
│                                                      │
│  💡 训练期间可以去做别的，界面不会锁住                    │
│     可以随时回来看进度、看日志                          │
└──────────────────────────────────────────────────────┘

训练过程中会存下多个轮次的权重，跑完自动评分分类，
好的几版留下来让你挑（见评测界面）。
```

## 6.2 设计要点

- **像赛马，不像进度条** —— 多组并排，一眼看出谁领先
- **"约剩多少分钟"比"百分之几"重要** —— 人关心的是"能不能先去吃个饭"
- **完成的立刻显示分数** —— 第一个跑完就出结果，不用等全部
- **界面不锁，但要能随时看** —— 可以切到合成台干活，切回来进度和日志都在
- **不把 CPU 压满** —— 提供占用控制，训练时电脑还能正常用

## 6.3 训练完成通知

```
┌────────────────────────────────┐
│  ✅ 训练完成                    │
│                                │
│  跑完了，自动评测结果：           │
│  🥇 ② v2ProPlus · 相似度 0.81   │
│  🥈 ① v2Pro     · 相似度 0.74   │
│                                │
│     [ 去看结果 ]    [ 知道了 ]   │

```

# 十一、技术实现约束

界面用什么技术做，会影响能做到什么程度。

| 需求 | 技术要求 |
|---|---|
| 数据地图（几百个方块） | 需要虚拟滚动，不能一次渲染 312×N 个 DOM |
| 波形显示 | 需要 canvas 或 WebAudio 绘制 |
| 无缝对比播放 | 需要 WebAudio，不能用 `<audio>` 标签（有延迟） |
| 实时进度 | 需要 WebSocket 或 SSE，不能靠轮询 |
| 拖拽导入 | 需要处理文件夹拖入（`webkitGetAsEntry`） |

**结论：界面建议用 Web 技术实现**，理由见 [`00-项目总览.md`](00-项目总览.md) 第八节。

# 十二、已定的界面决策

| 编号 | 问题 | 决定 |
|---|---|---|
| U1 | 主题 | **深色 + 浅色都要** |
| U2 | 界面语言 | **中文** |
| U3 | 窗口尺寸 | **全屏能用，小窗口也能用**（需要做响应式） |
| U4 | 专注模式 | **不做** |

## 关于 U3 的落实

既然"全屏能用、小窗口也能用"，以下界面必须做响应式：

| 界面 | 小窗口时怎么变 |
|---|---|
| 数据地图 | 方块变小、列数自动减少；详情面板改为浮层 |
| 标注 | 保持居中，按钮换行堆叠 |
| 合成台 | 情绪按钮换行；历史记录收起为折叠区 |
| 训练跑道 | 多组改为纵向排列 |

**不做专注模式**，所以流程导航始终可见 —— 这跟原则 1 是一致的。
